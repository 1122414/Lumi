# M1 四边离线比对

从仓库根目录运行，按顺序传入快门前预览、快门后预览、系统相册的原图。仅使用本机文件和 Python 环境（本次验证：Python 3.12.7、opencv-python 4.13.0.92、NumPy 2.4.6），没有 Android 依赖。

```sh
python3 tools/m1_framing/compare.py before.png after.png photo.jpg
```

前两张应只有取景画面。若是整屏截图，用 `--preview-rect X Y W H` 取两张图中相同的取景区域；不要对成片做额外裁切。用 `--ignore X Y W H` 排除固定调试文字和圆环在两帧中覆盖的位置，可多次指定，坐标相对于取景区域。例：若两张截图上的取景器为 `[0,451][1216,2072]`，可加 `--preview-rect 0 451 1216 1621`。工具读取 JPEG 时应用 EXIF 方向。

结果是 JSON。正数表示成片这条边向内收，负数表示比预览多拍到了内容；左右以原预览宽为分母，上下以高为分母。例如 600 像素宽的预览，左边报告 +1% 表示成片左沿约在原预览的第 6 像素处。“无法判断”有原因，没有偏差数值。正常完成比较（含无法判断）退出码为 0；读图或参数错误为非零。

**判定步骤**

1. 在同一个坐标网格（长边最多 1024 像素）比较快门前后的局部图案。若偏移后的图案明显更相似、原处内容改变，或稳定参照覆盖不足，四边都返回“无法判断”。不先把两张预览对齐。
2. 在成片和预览之间寻找双向唯一的特征对应点，排除明显离群点，估计从成片回到预览的尺度。明显旋转、剪切或整体对应不可信时不报数字。用原始对应坐标计算边界，没有把成片变形成与预览重合再比较。
3. 每边只使用在**两图中**距该边均不超过轴长 12% 的参照。至少需要 4 个位置、覆盖沿边方向 6 个分段中的 3 段、跨度至少 40%。用每个参照到边的距离估算边界，再取中位数。某边证据不足或分歧明显，仅该边“无法判断”。

**离线复现**

```sh
python3 tools/m1_framing/calibration.py /tmp/lumi-framing-demo
python3 tools/m1_framing/compare.py /tmp/lumi-framing-demo/preview.png /tmp/lumi-framing-demo/preview.png /tmp/lumi-framing-demo/crop-1pct.png
python3 -m unittest discover -s tools/m1_framing -v
```

样例输出到新目录；两次传同一张预览是为了构造已知静止的对照。分析真实拍摄时务必传**实际的前后两帧**。

测试图是生成的 600 × 800 非重复图案。左右各删除 6 像素、上下各删除 8 像素，真值分别为 1%；四边分别裁切时，其余边的真值为 0%。用例容差为 **±0.15 个百分点**，不代表手机验收容差。四边同时裁切的实测值（左、右、上、下）为 **1.002%、0.999%、1.002%、0.999%**。此外验证了只裁一边、不裁切、成片更宽、移动、缺少参照和实际 JPEG 命令行输入。

这个工具估计的是**画幅差**，不能从三张图推断由哪个相机环节造成。快门前后若恰好回到同一姿态，仍无法排除曝光瞬间的位移；低于图像分辨能力的变化也可能测不到。真实照片的结果应结合稳定机位与重复拍摄判断。
