## 提示词一：M3.0 模型接口入口

```text
你在仓库 /Users/geminchen/My-Item/Lumi 工作。先完整阅读：
1. plan_/11.18/2026-11-18_M3推荐构图重构与下一步开发指导.md（重点是第 4 节 M3.0 和第 5 节）
2. plan_/11.16/2026-11-16_安卓首版架构与开发顺序.md

## 背景
现在模型接口只能写在 local.properties 里，换模型要重新打包；接口还依赖 USB 和 adb reverse。
本次在取景界面上方增加模型接口入口，让我在手机上直接填写、测试和切换模型。

## 本次任务：只做 M3.0
1. 入口
   - 取景界面顶部增加「模型」入口，显示当前模型名（过长时截断）和状态：未配置、可用、上次失败。
     与现有右上角「调试」入口并存，不遮挡取景器。
2. 设置面板
   - 点开后可编辑：接口地址、模型名、API key。API key 默认隐藏，可临时显示。
   - 「测试连接」：用一张很小的内置测试图发一次与正式推荐相同格式的请求，结果区分为：
     地址不可达或超时、鉴权失败（401/403）、模型不支持图片或返回格式不对、成功，并显示耗时。
     测试请求不影响当前推荐。
   - 「保存」后立即生效：取消进行中的推荐请求，清除当前推荐和绿环，下一次推荐使用新配置。
   - 地址规则沿用现有逻辑（以 /v1 结尾追加 /chat/completions，或填完整地址），保存前校验格式。
3. 存储与安全
   - 配置保存在应用私有存储中。API key 用 Android Keystore 生成的 AES-GCM 密钥加密后保存，
     不使用已废弃的 androidx.security:security-crypto，不新增依赖。
   - API key 不得出现在日志、调试记录、截图可见的界面明文和崩溃信息中。
   - local.properties 中的三项只作为 debug 版首次启动、尚未保存过配置时的默认值。
4. 网络
   - debug 版允许明文 HTTP，便于填写局域网电脑地址脱离 USB 测试；使用 HTTP 且不是 127.0.0.1 时，
     在设置面板显示「明文传输，仅限可信网络」的提示。release 版只允许 HTTPS。
   - 调整网络安全配置时只改 debug 源集，不影响 release。
5. 记录
   - 调试版的推荐记录中增加所用模型名和接口主机名（不含路径参数和密钥），便于对比不同模型。
   - 现有针对 workbuddy/deepseek-v4.1-flash 的特殊参数，改为按模型名判断后附加，保持现有行为。
6. 单元测试（纯 Kotlin）
   - 地址拼接和格式校验；测试连接各类失败的分类；配置变更时旧请求结果被丢弃；
     默认值只在未保存过配置时使用；日志和记录文本中不包含 API key。

停止点：完成以上内容、通过验证并提交后停下汇报。不改推荐提示词和返回协议，不改绿环和轮廓逻辑（那是 M3.1、M3.2）。
```

## 提示词二：M3.1 稳定引导

M3.0 验收通过后再发。

```text
你在仓库 /Users/geminchen/My-Item/Lumi 工作。先完整阅读：
1. plan_/11.18/2026-11-18_M3推荐构图重构与下一步开发指导.md（本次任务的依据）
2. plan_/11.16/2026-11-16_安卓首版架构与开发顺序.md（产品交互和整体架构）

## 背景
M3 推荐构图链路已跑通，但真机上绿环闪烁、跳动、方向和位置经常不对，蓝色轮廓杂乱，原因见指导文档第 2 节。
M2 只用手机姿态投影绿环时，真机反馈是「绿环跟得住，停稳后提示可以拍」。本次回到这个思路，并把轮廓改为只分割一次。

## 本次任务：只做 M3.1，推荐协议不改
1. 绿环
   - 推荐成立后，目标姿态 = 发送那一帧的姿态 × Lens.lookAt(aimPoint)（Lens.lookAt 已存在）。
     每帧用 RotationProjection 把目标画面中心投影到当前取景得到绿环；目标在画面外时沿用现有贴边指回的逻辑（onView）。
   - 绿环位置只由手机姿态和镜头内参决定，不再用主体实测位置、背景核对或人脸位置去修正或隐藏它。
     去掉 measuredView、RingContinuity 以及 ReturnDirection 中依赖视觉证据的分支。
   - 只对显示位置做轻度平滑（例如时间常数约 80 毫秒的指数平滑），平滑不参与到位判断。
   - 推荐成立期间，只要有新鲜的姿态读数，绿环就每帧显示。
2. 可以拍
   - 当前姿态与目标姿态的角度差 ≤ 2°，且连续 ≥ 600 毫秒，期间角速度 ≤ 8°/秒，判定可以拍；离开容差立即撤销。
     阈值写成常量，注明为临时值，待真机标定。
   - 本阶段不用视觉结果门控「可以拍」。
   - 主体是人时，保留现有人脸检测做低频检查：同一张脸持续 1 秒以上偏离按姿态预测的位置超过画宽 15%，
     或持续 1 秒以上看不到，结束本次引导并提示「主体移动了，请重新推荐」。主体是物体时不做这项检查。
3. 蓝色轮廓
   - 只在推荐成立那一帧用现有分割得到一次轮廓，保存为发送帧取景坐标中的点列。
     之后每帧用 RotationProjection(发送帧观察, 当前观察) 投影这些点再绘制。
   - 停止逐帧分割和逐帧轮廓跟随（SubjectOutline.observe 等），推荐成立后分析帧中不再运行 MediaPipe 分割。
4. 界面状态
   - 取景器下方只保留：推荐中、引导中（显示十字理由）、可以拍、失败原因、主体移动了请重新推荐。
     GuideEvidence 中不再需要的状态一并删除。
5. 清理
   - 「记住这个构图」调试入口如能直接改用新的引导逻辑（aimPoint 取画面中心），就一并改，并删除不再被引用的旧类和旧测试。
     不确定某段代码是否仍被使用时保留，并在汇报中说明。
   - 不修改 PatchTracker、tools/m1_framing。
6. 单元测试（纯 Kotlin）
   - aimPoint 在中心时绿环与白点重合；偏右、偏上时方向正确。
   - 朝目标转动时绿环到白点的距离单调减小；转过头后绿环换到另一侧。
   - 转开 90° 后绿环贴边且指向正确，转回后回到原位置。
   - 停稳 600 毫秒才可以拍；快速掠过、未停稳时不可以拍；离开容差立即撤销。
   - 轮廓点随姿态投影的位置正确。
   - 人脸持续偏离或消失超过 1 秒时结束引导；物体主体不触发。

停止点：完成以上内容、通过验证并提交后停下汇报。不改推荐协议和提示词，不做选择题式推荐，不做 M4。
```

```text
## 背景
M3.1 已完成：推荐成立后，绿环和轮廓只由手机姿态投影，界面稳定。
剩下的问题是推荐本身：现在让大模型直接给主体框、主体内一点和推荐中心坐标，框经常不准，
推荐也常因置信度低或前后矛盾被拒绝。本次改为「手机算几何，模型做选择」。

## 本次任务：只做 M3.2
1. 主体候选
   - 在发送帧上用手机端检测器找出主体候选：人用现有 ML Kit 人脸检测（框扩展到大致上半身），
     物体用 ML Kit 目标检测（随应用打包的版本，单帧模式，允许多个目标）。
     新增 ML Kit 目标检测依赖前，在汇报中说明版本、包体积增量和许可。
   - 最多保留 4 个候选，按面积和离中心的距离排序，编号 1–4。
   - 在发给模型的 JPEG 上画出候选框和编号（框线和数字要醒目，不遮挡主体内部太多）。
2. 构图选项
   - 手机按每个候选主体生成固定的构图选项，例如：
     A 保持当前构图；B 主体在左三分线；C 主体在右三分线；D 主体居中；E 主体居中且头顶多留白；F 主体居中且头顶少留白。
     每个选项换算成保持当前倍率、原地转动或仰俯就能到达的目标中心；会让主体出画的选项不提供。
   - 选项定义写成常量和纯 Kotlin 函数，便于测试和以后调整。
3. 模型协议
   - 提示词说明：图中编号框是候选主体；请选一个主体编号和一个构图选项，并给出十字以内的理由。
     附上每个选项的文字含义。
   - 只要求返回 JSON：{"subject":编号,"option":"字母","reason":"十字以内"}。
     不再要求模型输出任何坐标、框或置信度。
   - 校验：编号或选项不在提供的范围内、理由超长时视为失败；不再用置信度拒绝。
   - 发送帧中没有检测到任何候选主体时，回退到现有的模型给框方式，并在日志中标明走了回退路径。
4. 选中后
   - 用选中候选的框作为主体，沿用 M3.1：在推荐帧分割一次得到轮廓，绿环由姿态投影，可以拍由角度容差加停稳判定。
5. 记录
   - 调试版继续在本地保留最近几次推荐的：候选数量、模型选择、是否回退、各段耗时，便于我对比。
6. 单元测试（纯 Kotlin）
   - 候选排序和编号；选项换算出的目标中心正确；会让主体出画的选项被排除。
   - JSON 解析和校验：合法选择通过；越界编号、未知选项、超长理由、多余字段被拒绝。
   - 没有候选时走回退路径。
```
