# Lumi 下一步产品与技术战略

## 1. 一句话战略判断

**Lumi 不跟 Doka 卷「滤镜海 + 云端重精修」，而是采用「云端自有 DS 大模型做摄影大脑 + 端侧 60fps 传感器与视觉跟踪做稳态执行」的务实端云组合：在按快门前真正看懂人、光、背景与机位，一次只给一条最值钱的可执行动作，把普通人带到明显更好看的成片。**

当前阶段的核心目标，是从「能跑通构图绿环的工程原型」，升级为「在真实人像与旅行场景下，盲测成片明显胜过原生相机与 Doka 基础构图」的 AI 拍摄导演相机。

## 2. 现状盘点：Lumi 已经做到哪，还差什么

对照当前代码（含工作区最新实现）与 [GPT 产品定位文档](https://chatgpt.com/s/t_6b06b25918e48191abcad0ed31bafb06)，Lumi 的资产与断层非常清晰：

### 2.1 已建成的核心资产
- **已脱离 USB，直连自有云端 DS 视觉模型**：具备应用内模型热配置（`ModelSettingsDialog`）、加密凭据存储、推荐耗时与叠加诊断图（`CompositionDiagnostic`）。
- **稳定低耗的端侧引导底座**：`PoseGuidance`（纯姿态投影 + 80ms 指数平滑 + 角度容差停稳判定）叠加 `SubjectTracker`（~1ms/帧轻量 2D 颜色跟踪补偿近景视差与主体微动），已解决逐帧分割抖动问题。
- **语义化构图与本地零延迟预设**：`CompositionChoice` 将构图收口为 7 种语义动作（`keep / center / left_third / right_third / tight_top / more_headroom / pull_in`），取景器底部 5 档预设（`智能 / 三分·左右 / 对称 / 紧凑 / 留白`）支持本地即时切换，且已适配动态变焦倍率与前后摄切换。

### 2.2 距离真正产品化的 5 个核心断层

| 断层 | 当前代码现实 | 对真实体验的影响 |
| --- | --- | --- |
| **1. 主体定位仍依赖 VLM 吐坐标** | `ChatProtocol` 仍要求 DS 返回 `box` 和 `point`；`CompositionAnalyzer` 用 `detection?.result?.singleOrNull()` 检测人脸 | 框偏导致分割或构图拒识；**两人及以上合照直接无法检测人脸**；用户无法点选自己想拍的主体 |
| **2. 云端请求载荷偏重 + 等待感裸露** | `RecommendationFrame` 固定发长边 `768px` / 质量 `85` 的图，DS 需输出完整主体坐标与描述，且等待期间界面无端侧即时锁定反馈 | 端到端响应偏慢（3–6 秒），请求期间像黑盒干等，打断旅行/街拍节奏 |
| **3. 引导维度单一** | 只覆盖原地转动/仰俯，未把焦段建议、横滚水平仪、挪步机位纳入闭环 | 画面歪斜仍提示「可以拍」；背景杂乱时不会建议切 2× 或退 0.6×；无法解决人背重叠（拱门/路牌） |
| **4. 缺少“摄影导演”P1 能力** | 只给构图方向和十字理由，不做光线、背景避障、人像姿势一句提示 | 对普通人拍人像帮助上限偏低，容易被感知为“高级九宫格” |
| **5. 缺少成片闭环与外场盲测** | 拍完仅存 CameraX 默认原图，无主体联动对焦测光、无拍后复盘/二次裁切，无对照评测数据 | 无法证明「跟着 Lumi 拍真的更好看」，直出观感也易吃亏 |

## 3. 竞品对标：拆解 Doka 相机（闭源标杆）与端侧模型路线评估

### 3.1 Doka 真实技术架构核实（并非纯端侧）
核实 [Doka 相机官方安卓隐私政策（2026-11-16 版）](https://www.yindoka.com/web/android/privacy_policy) 与应用商店信息（[官网](https://www.yindoka.com/official/)、[App Store](https://apps.apple.com/us/app/doka-cam/id6751240418)、[小米应用商店](https://r.app.xiaomi.com/details?id=com.ydgn.doka)），其架构同样是**端云协同**：
- **云端视觉分析**：开启 AI 构图/滤镜推荐时，将取景框临时帧与焦距/方向等参数上传至自家服务端，调用**阿里云视觉能力**（结合其基于手机摄影数据训练/微调的构图模型）返回构图与焦段建议；AI 摄影师精修则调用**火山引擎**。
- **手机端侧**：陀螺仪/加速度/重力传感器本地算 AR 引导线与水平仪，配合 OpenCV / GPUImage / uCrop 与手机厂商相机优化 SDK 做本地跟踪、滤镜渲染、裁剪与成像。

**结论**：Doka 能在老机型上做到 1–2 秒出引导，不是靠在手机上硬跑大模型，而是靠**传小图 + 极短结构化输出 + 云端快推理**。Lumi 走自有云端 DS 路线在架构上并不吃亏，且在语义理解深度上具备明显上限优势。

### 3.2 Doka 体验对比与攻防点
结合跨平台真实用户评价（[AppRank](https://apprank.net/zh/app/app-36336/)、[MWM](https://mwm.ai/apps/dokaxiang-ji/6751240418)、[AppTail](https://apptail.io/app/doka-cam-NNTw/taiwan)）：

| 维度 | Doka 的真实表现 | 市场与用户反馈 | Lumi 的应对策略 |
| --- | --- | --- | --- |
| **构图原理与上限** | 云端视觉分析 + 经典比例/裁切框 + AR 线（地平线、建筑垂直线、美食框），1–2 秒出结果 | 风景和静态场景上手快，但中差评反复吐槽「大多是画面中心放大」「算法套固定模板」「AI 球跳动/突然消失」 | **正面超越**：保留 Lumi 姿态+跟踪的稳定优势，用云端 DS 语义解决背景避障、人景关系与机位建议，不只做 2D 裁切 |
| **焦段与景别** | 支持 AI 多景别构图（全身/半身/特写）与拍后一键多种美学二次裁剪 | **二次构图裁剪**是好评最集中的高频实用功能之一 | **必须吸收**：S1 先把拍前推荐倍率融入构图；S2 基于已有主体掩码补齐端侧零成本二次裁切 |
| **主体意图控制** | 支持手动框选主体，但默认算法较死板 | 用户明确要求「按我的意愿围绕画面里的 XXX 构图，而不是强塞既定标准」 | **体验领先**：S1 落地取景器轻点即锁定主体 + 端侧候选框，让用户意图与 DS 判断自然融合 |
| **人像深度指导** | v2.2 推出 AI 人像摄影师 Romy，主打构图 + 专属装备 + 拍后精修 | 5 星好评里也在催更：「希望顺便给模特一句手怎么放、看哪里的姿势提示」；缺多人合照 | **核心差异化**：S1 先补齐多人合照；S2 把「姿势一句提示 + 光线方向」做成 Lumi 人像核心卖点 |
| **成片与滤镜** | 胶片/CCD 滤镜 + AI 场景推荐滤镜 + 付费按次精修 | 普通用户买单「拍完直接好看」，但对订阅贵（$69.99/年 + 精修另收费）与水印反感 | **克制补底**：不卷百款滤镜，但先做好基础成像（主体联动 AF/AE 对焦测光 + 硬件扩展能力），避免原片灰暗输掉盲测 |

### 3.3 公开端侧小模型评估与务实选型结论

| 路线 | 代表公开模型 | 优点 | 现实硬伤 | Lumi 决策 |
| --- | --- | --- | --- | --- |
| **专用构图/裁剪小模型** | [FocalNet](https://github.com/appwrite/focalnet)（19.45 MiB ONNX，RepViT-M0.9 + 人类美学裁剪头）、GAIC、CACNet、LiveCompose | 几十毫秒本地出裁剪框，零流量成本 | 完全不懂语义，看不懂背景避障、逆光或人像姿势 | **暂不替代 DS**；留作 S2/S3 离线构图兜底与拍后一键美学二次裁剪的候选 |
| **端侧微型 VLM** | Qwen3.5-0.8B / Qwen3-VL-2B（NPU）、SmolVLM2-500M、Gemma 3n E2B（LiteRT-LM） | 完全离线、无网络往返 | 吃 1.5–3GB 内存、强依赖高通旗舰 NPU（退回 CPU/GPU 延迟 5–30 秒）、摄影审美显著弱于云端 DS | **现阶段明确不上**，避免陷入机型碎片化与内存发热泥潭 |
| **务实端云组合（采用）** | **云端自有 DS（摄影大脑）+ 端侧 ML Kit / Magic Touch / PoseGuidance / SubjectTracker（60fps 执行器）** | 审美与场景理解上限高、安卓全机型通吃、包体与内存可控 | 受云端模型 TTFT 与网络影响，真实延迟约 1.5–2.5 秒 | **S1~S2 主力架构**：通过 512px 缩图 + 超短选择题 JSON + 连接复用把云端压进 ~1.5–2.5 秒，并用端侧 0.2 秒即时反馈藏住等待感 |

## 4. 明确的产品边界（现阶段不做什么）

1. **不做滤镜商城 / 百款胶片调色 / 重度磨皮美颜**。
2. **不做云端生成式 AI 精修（换天、重绘、P 路人）**。
3. **默认界面保持零门槛**：专业曝光参数（`EV / ISO / S / WB`）以折叠式 `M手动` 面板 + 单项 `AUTO` 半自动优先 + `AI自动挡` 提供，绝不把小白挡在取景器之外。
4. **不做自由开放式多轮聊天摄影教练**：取景器中严禁堆砌长段文字和摄影术语，坚持**一次只解决最关键的 1 个问题**。
5. **现阶段不上端侧大参数 VLM**。

## 5. 分阶段升级路线图

### 阶段 S1：补齐体验基线与端云分工重构（当前执行阶段）

**目标：** 把 Lumi 从“室内调试原型”变成“随时可带出门拍单人/多人/景物、响应明显提速、支持点选主体与焦段联动、带水平仪和主体对焦测光”的日常可用相机。

#### S1 端侧 vs 云端 DS 分工表

| S1 子项 | 云端通用大模型（DS）职责 | 端侧技术职责 |
| --- | --- | --- |
| **S1.1 端侧候选框 + 点选主体 + 多人合照** | **审美与主角决策**：看带编号框（或用户点选星标 `★`）的取景图，只输出选中编号、构图选项、可选焦段与十字理由，**不再手算像素坐标**（仅在 0 候选时回退旧协议） | 修复 `CompositionAnalyzer` 的 `singleOrNull()`，支持多人人脸并自动合成「多人合照」候选；结合端侧目标检测生成 1–4 号候选框画在送审图上；支持取景器**轻点选主体**并直接作为 `SubjectSegmenter` 分割种子 |
| **S1.2 推荐焦段与景别联动** | **场景景别决策**：结合当前倍率与设备真实可用光学档位（如 `0.6x / 1x / 2x / 3x`），判断该保持当前倍率还是切换更合适的焦段 | `RearZoomStops` 提供真实可用档位给协议；取景器弹出「建议切至 `2×`」一键按钮；切换倍率后**保留当前推荐**，由 `RememberedComposition` 在新倍率下无缝衔接绿环与轮廓 |
| **S1.3 横滚水平仪 + 到位微交互** | 不参与 | 纯端侧：`CameraPose` 四元数解算横滚角（俯仰拍桌/仰拍天空自动静默），在中心白点旁绘极简水平短线（±1.5° 内变绿，纳入水平拍摄到位条件）；到位上升沿轻震反馈；提供可选「自动拍」开关（到位停稳 0.8s 自动快门） |
| **S1.4 云端 DS 提速 + 主体 AF/AE 对焦测光** | 接收 `512px` 缩图与超短选择题提示词，输出 ~20 token 紧凑 JSON，关闭默认深度思考 | `RecommendationFrame` 缩图由 `768px/Q85` 降至 `512px/Q75`；`VisionChat` 正常结束保留底层连接池复用；点推荐/点选主体后 0.2s 内先显示端侧锁定框或对焦圈；锁定主体后自动触发 CameraX `FocusMeteringAction` 对主体对焦测光 |

#### S1 验收标准
- **主机验证（无真机时必跑）**：`./gradlew :app:assembleDebug`、`./gradlew :app:testDebugUnitTest`、`./gradlew :app:lintDebug` 全通过；新增纯 Kotlin 单测覆盖候选框排序/多人合照合成、极简选择题协议与回退解析、焦段推荐校验、四元数横滚角解算与水平仪到位判定。
- **真机外场验收（拿回手机后验证）**：10 个真实场景（单人/多人/静物混合）推荐成功率 ≥ 90%；轻点画面即可锁定指定主体并同时完成对焦测光；建议切换焦段时一键切倍率且绿环无缝衔接；云端 DS 推荐耗时中位数显著下降（目标 ≤ 2.5s）。

---

### 阶段 S2：打造超越 Doka 的“实时摄影导演”（中期，S1 盲测后启动）

1. **S2.1 单点最高优先级执导协议**：每次分析由 DS 按问题严重度只输出 **1 条主执导动作**（构图/焦段、背景避障/机位、光线利用、人像姿势一句提示四选一，文案 ≤ 12 字且零术语）。
2. **S2.2 AI 主动程度分级（回应 GPT 问题 #2）**：三档模式——`安静`（仅水平仪与手动线）、`主动`（端侧停稳 ≥ 0.8s 或检出切头/大歪斜/严重欠曝时自动静默触发一次，移动或拍完进入冷却）、`手动`（点按钮或点选主体触发）。
3. **S2.3 拍后 3 秒轻复盘 + 端侧二次构图**：快门旁缩略图展开轻复盘卡，提供一句复盘 + 基于主体掩码（或可选 FocalNet 19MB ONNX）生成的 2 个美学二次裁剪方案，保留原图底片。

---

### 阶段 S3：技术护城河与审美闭环（已完成）

1. **M4 跨视差「挪步」引导**：用主体与背景锚点的相对视差位移驱动绿环，解决「人落进拱门」「躲开背后柱子」等原地转动无解的构图问题。
2. **「好照片」多维评价体系与本地偏好记忆（回应 GPT 问题 #1）**：拆分主体清晰突出 × 画面平衡 × 背景干净度 × 自然度四个维度，本地轻量记忆用户构图偏好作为 DS 先验。

---

### 阶段 S4：专业光影参数层（实时测光遥测 + M 手动挡 + AI 自动挡，已完成）

*与参考图功能完全解耦，日常任何场景均可独立使用。*

1. **端侧实时物理光影遥测**：
   - 从 Camera2 `TotalCaptureResult` 直读每帧真实 `ISO`、快门 `S`、物理光圈 `f/`（可变光圈机开放真实档位，固定光圈机如 PKX110 展示只读 `f/1.88`）、当前 `EV`；
   - 接入 `Sensor.TYPE_LIGHT` 实时读取环境照度 `Lux`，叠加端侧画面均亮、高光溢出率、暗部占比及「主体 vs 背景亮度差」（定量判别顺光/逆光/大光比），一并喂给云端模型，彻底消除模型盲猜曝光。
2. **三档曝光模式（`自动` / `AI自动` / `M手动`）**：
   - **`AI自动` 按主动程度区别对待**：`手动` 模式下弹出确认胶囊（点击应用）；`主动` 模式下直接平滑生效并支持一键 `[还原]`；`安静` 模式下不干预。
   - **`M手动` 支持单项 `AUTO` 半自动优先**：`EV / ISO / S / WB` 每项均带独立 `AUTO` 档（如仅锁快门 `S` 防手抖、`ISO=AUTO` 时端侧按最新测光基线自动配平 `ISO`，防拍黑拍爆），并支持一键「抄 AI 参数」微调。

---

### 阶段 S5：参考图导演（Reference Coach：复刻 + 超越复刻，已完成）

*完全独立的可选能力：导入参考图后，用户可自由决定自己调/自己拍、开绿环/挪步引导，或叠开 AI 自动挡。*

1. **参考图一次性拆解「拍摄处方（Shot Recipe）」**：提取构图位置/景别/机位仰俯、光影方向与基调（顺光/侧光/逆光/冷暖）及人像动作要点并本地缓存。
2. **取景器缩略图 + 可选 25% 半透明叠图**：默认仅挂小缩略图保持视野干净，点按可切换 25% 半透明叠图对照或展开处方卡。
3. **同机位打卡人像「复刻 + 超越复刻」双轨执导**：
   - **可直接复述的动作修正口令（复刻）**：对比参考图与现场模特当前动作，给出摄影师可直接张嘴念出的口语纠偏；
   - **「超越复刻」升级建议**：结合现场更有利的真实光线/前景/构图机会，给出让成片超越原图的额外建议；同时联动绿环、M4 挪步与光位建议。

## 6. 科学验证方案：用外场双盲测试驱动迭代（回应 GPT 问题 #3）

**硬性原则：在 S1 真机可用后、启动 S2 之前，完成一轮外场双盲对照实验（M3.3）。**
